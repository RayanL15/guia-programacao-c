Aprendi que o Git é uma ferramenta de controle de versão usada para acompanhar alterações em projetos. Já o GitHub é uma plataforma online onde os repositórios Git podem ser armazenados, compartilhados e revisados.

Também aprendi que os commits registram mudanças feitas no projeto, enquanto as branches permitem trabalhar em alterações separadas sem mexer diretamente na versão principal. Depois, essas alterações podem ser unidas usando merge.

O Pull Request serve para propor e revisar mudanças antes de integrá-las à branch principal. Durante esse processo, podem surgir conflitos, principalmente quando duas branches alteram a mesma parte de um arquivo, e esses conflitos precisam ser resolvidos manualmente.

Uma das dificuldades foi entender a diferença entre branch, commit, merge, rebase e os comandos de sincronização com o repositório remoto. Com a prática, esses conceitos ficaram mais claros.

Esse conhecimento pode ajudar bastante em projetos futuros, principalmente para manter o código organizado, trabalhar em equipe, recuperar versões anteriores e registrar melhor as mudanças feitas no projeto.
